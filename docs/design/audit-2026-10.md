### Implementation integrity verdict — pass

The board is authored for this product: serif column tabs, paper/sheet surfaces, a single ink timer ring, fixed-size sheets. Nothing is category boilerplate. Detector (`impeccable detect --json components pages layouts app.vue`): exit 0, 17 advisory findings, 0 anti-patterns, 0 new against `baseline.json`.
- **Font sizes (9):** `BoardColumnHeader.vue:65,81` (1.75/2rem, the responsive display steps, so DESIGN.md should list them); `TaskCard.vue:211,370,391`; `TaskAnimatedModal.vue:326`.
- **Radii (6):** `TaskAnimatedModal.vue:341` 0.375rem is real drift. `TaskCard.vue:361` 9999px is a full circle, which DESIGN.md allows, so it is a false positive.
- **Colours (2):** `TaskAnimatedModal.vue:274,416` rgba scrim and close values.
- **Out of scope:** the 7 findings in `pages/dnd-sample.vue`, a dev page.
- **Not re-checked:** `main.css` was excluded from this scan, so its 27 baseline entries were not checked again, not fixed.

Integrity is weakened by three semantic drifts the regex detector cannot see: KPI colours on statistics, raspberry timebox rings on done cards, mixed icon sets (see F4, F7, F13).

### Findings

**P0 — none.** Every core-loop step can be completed with a pointer.

**[P1] F1 Task detail dialog: no initial focus, no real trap, no focus return** — Accessibility
- Location: `composables/useModalBehavior.ts:82` (`handleFocusTrap`), `components/task/TaskAnimatedModal.vue`
- Observed: after opening a card, `document.activeElement` stays on the board card. 10 Tab presses walk through board cards and actions behind the scrim before reaching "Schließen". After Esc, focus lands on `<body>`, not the card.
- Cause: the trap only wraps when focus is already on the first or last element inside the modal.
- WCAG: 2.4.3 Focus Order, 2.1.2.
- Severity: the design review rated this P0. It stays P1 here because keyboard users can still reach the dialog after about 10 Tab presses.
- Fix: replace with `USlideover`/`UDrawer`, whose reka-ui FocusScope handles initial focus, trap and return. This is the decided P2 pattern, so do it as part of P2.
- Interim fix in `useModalBehavior.ts:115-158`:
  - `watch(isOpen)` never fires when the modal is mounted already open, so call `focusFirstElement()` on mount.
  - Store `document.activeElement` on open and restore it on close.
  - In the trap, pull focus back in when it is outside the modal.
- Supersedes A9.
- Command: `/impeccable harden`

**[P1] F2 Keyboard path to the core loop: cards cannot be opened from the keyboard, and drag announcements are English with raw IDs** — Accessibility
- Location: `components/task/TaskCard.vue:19-20`, `components/board/SortableTaskWrapper.vue`, `components/board/Board.vue:12` (`<DragDropProvider>`)
- Observed:
  - On the focusable `.task-wrapper` (role=button, `aria-roledescription="draggable"`), Enter and Space both start dnd-kit's keyboard drag. Neither opens details.
  - The live region announces "Dragging was cancelled. Draggable item seed-open-1 was dropped." That is English, with an internal ID, in a German UI.
  - The card's accessible name is the whole card text.
  - On desktop, details open only on **double-click**: a single mouse click on title or body did not open them in Chromium; a touch tap does. So the keyboard path to details is only the context menu, and opening it from the keyboard is unverified.
- Standards: WCAG 2.1.1 Keyboard; the PRODUCT.md promise "fully keyboard-operable (including board moves)"; the language policy.
- Fix:
  - Enter opens details; Space keeps lifting the card.
  - Pass German i18n `accessibility.announcements` and `screenReaderInstructions` to `DragDropProvider`, using task titles instead of IDs.
  - Give the wrapper `aria-label` = title.
  - A single click should open details on desktop too; keep the drag activation distance.
  - Then add the P3 shortcuts (1–4 move the focused card).
- Command: `/impeccable harden`

**[P1] F3 "Add task" is hover-only; missing on touch and keyboard** — Responsive / Accessibility
- Location: `components/board/BoardColumn.vue:372` (`shouldShowAddButton` needs `isHovering`). `handleFocusIn`/`handleFocusOut` at :411 are no-ops.
- Observed: at 390px the Offen tab has no add affordance at all. On desktop it appears only while the mouse is over the column.
- Fix: implement the decided quick add (P3: `n`/⌘K → `UCommandPalette`). Until then, show the soft add button persistently at the bottom of Offen and on focus-within.
- Command: `/impeccable adapt`

**[P1] F4 Status colours used as decoration on statistics** — Theming
- Location: `pages/statistics.vue:57-81`
- Observed: the five KPI numbers are ink, teal, orange, orange and sky-blue. "Ø Schätzgenauigkeit 100%", a perfect result, is rendered in attention-orange. Teal and info KPIs fail contrast (2.3:1, 2.7:1, already listed as A8).
- Rules broken: "The Status Is Not Decoration Rule" and "The One Lamp Rule". `text-info` is not part of the palette at all.
- Fix: all KPI numbers `text-highlighted`, set by typography (Instrument Serif display numerals would suit). Colour only for a genuine deviation, e.g. a warning badge when accuracy is outside 80–120%.
- Command: `/impeccable quieter`

**[P1] F5 Mobile statistics time-frame select shows the raw value `today`** — Responsive
- Location: `pages/statistics.vue:23-28`
- Observed: the `<USelectMenu>` uses Nuxt UI v2 props (`:options`, `option-attribute`, `value-attribute`), so v4 ignores them: the menu has no items and shows the raw `today`.
- Fix: `:items="timeFrameItems" value-key="value"` (label-key defaults to `label`).
- Command: `/impeccable harden`

**[P1] F6 No WIP-limit feedback at all** — Pattern gap (P4 verified)
- Location: `composables/useBoardDndKit.ts:66-79` sets `dragState.isDropBlocked`, but nothing reads it. The only other reference is its declaration in `composables/useBoardDragState.ts`.
- Observed: dragging a second card over the full Jetzt column shows the overlay hovering with no hint. On release it silently snaps back.
- Fix: bind `isDropBlocked` to `BoardColumn` (Jetzt) and show one Graphite line ("Eins nach dem anderen — erst abschließen oder parken.") as an i18n key. No red, no shake, 160ms fade.
- Command: `/impeccable clarify`

**[P2] F7 Timebox overrun ring turns raspberry, even on done cards** — Theming
- Location: `components/task/TaskProgressCircular.vue:132-133` (`>= 100 → 'error'`)
- Observed: both cards in Erledigt carry a raspberry ring. DESIGN.md: orange = overdue timebox, raspberry = destructive or failed only.
- Impact: the peak-end moment of the day is marked as failure.
- Fix: overrun → `warning`. On done cards, drop the escalation and show the neutral spent/planned label.
- Command: `/impeccable colorize` (restraint pass)

**[P2] F8 Mobile: board actions only on the Erledigt tab; targets 32px** — Responsive
- Location: `components/board/BoardSyncControls.vue`, mobile layout in `assets/css/main.css` (~:398)
- Observed: the stats, stack, settings and refresh icons are positioned inside the third 100vw panel. They sit off-screen on Offen and Jetzt.
- Measured sizes: icons 32×32; "Aufgabe archivieren" and "Statistik öffnen" 32px tall; sort toggle "Manuell" 91×24.
- Fix: dock the action row above the tab bar, independent of the panel. Raise to ≥44px hit areas (`size="lg"` or padding on the ghost buttons).
- Command: `/impeccable adapt`

**[P2] F9 Reduced motion not honoured for the mobile column slide** — Accessibility / Motion
- Location: `assets/css/main.css:398-400` (`transition: transform 320ms`, `will-change: transform`)
- Observed: unchanged under `prefers-reduced-motion: reduce`. 320ms is also outside the 150–220ms band.
- Other gap: only `TaskProgressCircular.vue:280` has a reduced-motion block. The modal entrance and stack animations are covered only incidentally.
- Fix: 220ms and `@media (prefers-reduced-motion: reduce) { .board { transition: none } }`. Drop `will-change` at rest and set it only while `.dragging` or switching.
- Command: `/impeccable animate`

**[P2] F10 Statistics table scroll region not keyboard-focusable on mobile** — Accessibility
- Location: `components/statistics/TasksTable.vue` (`.overflow-auto` wrapper)
- axe `scrollable-region-focusable` (serious) at 390px. The header "Geplante Zeit" is clipped mid-word.
- Fix: `tabindex="0"` + `aria-label` on the wrapper, or a stacked row layout under `md`.
- Command: `/impeccable adapt`

**[P2] F11 /tasks has no `<main>` and no `<h1>`** — Accessibility
- Location: `pages/tasks.vue`, `components/board/Board.vue:14`
- Landmarks are only the mobile `<nav>` and the toast region. Column names are `h2`, and "✓ Erledigt" includes the glyph in its accessible name.
- Fix: wrap the board in `<main>` and add a visually hidden `<h1>` ("Heute"). Mark the ✓ `aria-hidden`.
- Command: `/impeccable harden`

**[P2] F12 200% text: Erledigt pushed off-canvas at 1440** — Responsive
- Observed: with root font-size at 200%, scrollWidth is 2208/1440. Chips stay 10px (`text-[10px]` / `text-2xs` are px), and "30 min" overflows the progress ring.
- True browser zoom reflows to the mobile layout correctly.
- Fix: rem-based chip size (`text-2xs` → 0.6875rem per DESIGN.md label). Board columns `minmax(0,1fr)`; let the ring label hide below a threshold.
- Command: `/impeccable adapt`

**[P3] F13 Mixed icon sets** — Theming
- 83 `i-heroicons-*` usages in 20 files (e.g. archive toast `Board.vue:460`, statistics refresh `pages/statistics.vue:30`). The rule is Phosphor only.
- Fix: mechanical swap to `i-ph-*`; add an ESLint `no-restricted-syntax` guard.
- Command: `/impeccable polish`

**[P3] F14 Dead/duplicate files**
- `components/task/TaskDetailContent.new.vue`, `components/onboarding/OnboardingWelcome.vue` (C2 note), `pages/dnd-sample.vue` ships in the build.
- Fix: delete or move behind dev-only routing.
- Command: `/impeccable distill`

### Systemic patterns
- **Focus and keyboard handling is hand-rolled:** custom modal, custom trap, hover-gated affordances, no-op focus handlers. Moving to Nuxt UI overlays (P2) and adding the shortcut layer (P3) fixes F1–F3 at the root.
- **Colour carries "good/bad" judgement** in three places: KPIs, timebox ring, archive toast `color: 'success'`. Calm needs neutral defaults with colour only for genuine deviations.
- **Dimming is used as hierarchy** (focus mode, waiting, done wash). It produces most axe failures (A1–A5). One decision on "dimmed but readable" (≥4.5:1 for titles) would resolve a whole class.

### Positive findings
- Undo instead of confirm is already real for delete (context menu and detail menu, 5s `UToast` with "Rückgängig") and for archive. P1 can be closed for those flows.
- No horizontal overflow on any view at 390px; bottom tabs are 130×59 with `aria-current`.
- The task-card focus ring (from `test/focus-states`) is visible, ink, radius-matched, and undims the column under focus.
- Optimistic moves: drops apply instantly with no spinner.
- The theming layer is clean: only 6 raw colour literals in components; tokens flow from `main.css` → Nuxt UI.

### Recommended actions
1. **[P1] `/impeccable harden`**: F1 (dialog focus via P2 slideover/drawer), F2 (Enter/keyboard moves), F5 (USelectMenu v4 props), F11 landmarks.
2. **[P1] `/impeccable adapt`**: F3 persistent add affordance on mobile, F8 action row docking + 44px targets, F10, F12.
3. **[P1] `/impeccable clarify`**: F6 calm WIP hint copy + wiring.
4. **[P1] `/impeccable quieter`**: F4 statistics KPIs neutral.
5. **[P2] `/impeccable colorize`** (restraint): F7 timebox ring semantics.
6. **[P2] `/impeccable animate`**: F9 reduced motion + 220ms slide.
7. **[P3] `/impeccable polish`**: F13 icons, F14 dead files, ramp drift (C4).

## Part 2 — Critique (UX)

Method: dual-agent. Assessment A (design review) and Assessment B (detector and browser evidence) ran as isolated subagents.
- **Rerun:** the first run of A died on a session rate limit, so A was rerun on the rebased code.
- **Ordering caveat:** B's results reached the parent before A finished. A itself never saw them, so A's judgement is unanchored. The parent synthesis is not strictly isolated from B.

### Design specificity verdict

**Design review (unanchored):** the board is unmistakably this product: serif binder tabs, paper sheets, one ink ring, Jetzt stacked over Wartet, the teal done wash. Statistics and settings are not. Statistics is a stock Nuxt UI dashboard (KPI grid, pills, table) and settings is a generic option-card list. The welcome screen (blurred leaf photo, red/black/white brand CTAs) is a third, louder world that fights the paper palette.

**Deterministic scan:** the detector agrees on structure, with 0 anti-patterns. It flags 17 ramp drifts in board, card and modal files (see Part 1). The overlay contrast pass matches the review's complaints:
- column h2 at 1.7:1 in focus mode
- 10px chips (undersized-ui-text ×10)
- priority-high at 2.0:1
- teal on teal at 2.6:1 and white on teal at 2.3:1
- statistics KPI text at 2.3:1 and 2.7:1

The detector cannot see the status-colour semantics that the review raised (raspberry ring, orange "100%"). One false positive: `TaskCard.vue:361` 9999px is an allowed full circle.

**Overlay:** injection succeeded headless, so there was no `[Human]` tab and no overlay is visible to the user.

### Overall impression

The board itself is close to the Quiet Desk. Its problems are mostly missing feedback and missing paths, not visual noise:
- the hint when the lamp is taken
- a keyboard route
- an add button you can see
- a calm close to the day

The biggest opportunity is the **Jetzt moment**. It is the product's whole thesis, and today it is the place where the UI says the least.

### What's working
1. **Typography carries hierarchy.** Instrument Serif tabs, Figtree content, generous space. The One Lamp Rule holds on the board: the in-progress ring is the only ink.
2. **Undo replaces confirm.** Delete and archive act immediately with the task name and a countdown bar (P1 done for these flows).
3. **Mobile tabs with counts in the thumb zone** (130×59), plus the new solid ink focus ring on cards.

### Priority issues
1. **[P1] Jetzt refuses silently** (F6, P4). This is the core rule, invisible at the moment it applies.
   - Fix: a Graphite one-liner under the Jetzt header while the drop is blocked.
   - Later, consider **swap with undo**: the current task goes to Wartet, with a toast.
   - Command: `/impeccable clarify`
2. **[P1] Keyboard path broken** (F1, F2): no focus in or out of the detail, Enter does not open, English announcements.
   - Fix: P2 slideover/drawer plus German dnd-kit announcements plus Enter-to-open.
   - Command: `/impeccable harden`
3. **[P1] Add task is invisible** (F3), and it is the first step of morning planning.
   - Fix: a persistent ghost "Aufgabe hinzufügen" under Offen, a thumb-reach add on mobile, then P3 quick add.
   - Command: `/impeccable adapt`
4. **[P2] Status colour as judgement** (F4, F7, plus the solid teal archive button).
   - The raspberry ring on a done card spoils the peak of the day.
   - Orange "100% Schätzgenauigkeit" reads as a warning.
   - Command: `/impeccable quieter`
5. **[P2] The faintest column holds the next decision.** Focus-mode dimming makes Offen titles about 2.5:1 (A5).
   - Fix: keep Offen readable (titles ≥4.5:1) and dim only the chrome (badges, topic), or dim only on mobile panels that are not in view.
   - Command: `/impeccable typeset`

### Persona walk-through: the core loop (glance → move → timer → close)

**Morning-glance solo worker** (10 seconds, 20× a day):
- **Glance:** Jetzt reads instantly. Offen is the faintest thing on screen, and in Erledigt yesterday's card plus two buttons push today's wins down.
- **Move:** the drag lift is lovely: an elevated sheet with a slight tilt. Onto a full Jetzt, it bounces back without a word.
- **Timer:** starts automatically, but "0 min" plus a dot is ambiguous. Is it running?
- **Close:** the drop on Erledigt gives the teal wash and a whispered "Gut gemacht!", undercut by a raspberry ring. There is no end-of-day moment; review is a spreadsheet.

**Alex (power user):**
- No `n` / `⌘K` / `j` / `k`.
- Every inspection costs a double-click.
- Changing status by keyboard means the 6-item context menu and then a submenu.

**Sam (keyboard / screen reader):**
- The first Tab stop is the invisible sort toggle.
- Enter lifts instead of opening.
- In the detail, Tab walks 10 board controls behind the scrim, and Esc drops focus to `<body>`.
- Hears "Draggable item seed-open-1 was dropped."

**Casey (one-handed mobile):**
- No add button.
- The detail is a centred modal with its X top-right, out of thumb reach (P2 drawer).
- Board actions exist only on the Erledigt tab, at 32px.
- Moving a card needs a long-press plus a 650ms edge dwell; the alternative is the context menu.

### Cognitive load: 3 of 8 checks fail (moderate)
- **Minimal choices:**
  - The context menu has 6 items, 3 with submenus.
  - Statistics shows 5 period pills, 2 tabs and 5 KPI tiles at once.
  - The detail header has 5 chips plus a ⋮ menu, and the timebox is offered twice ("+ Timebox" chip and the "Timebox setzen" link).
- **Visual hierarchy:** dimmed Offen (A5).
- **One thing at a time:** two inline buttons in Erledigt ("Aufgabe archivieren", "Statistik öffnen"); the second duplicates the chart icon bottom-right.

### Minor observations
- Welcome copy: "persoennliches" should be "persönliches", and "lasse dir" should be "lass dir" (`i18n/locales/de.json:656`). The brand should be "Kan-Do".
- Settings is titled "Modus-Einstellungen". It shows the current mode twice ("Aktueller Modus" and the checked card) and has both a footer "Schließen" and an X.
- Archive button is singular ("Aufgabe archivieren"); the toast is plural ("Aufgaben archiviert").
- The task detail title is Figtree, while the settings modal title is serif, which is inconsistent. DESIGN.md says modal titles are `font-display`.
- "Metadaten" in the task detail exposes integration internals (Principle 5). Keep it collapsed, or move it to the ⋮ menu.
- The delete toast sits on top of the bottom-right board actions for 5s.

### Questions to consider
1. *(proposed 2026-10-20: column stays; the card grows over its slot instead — DESIGN.md "The current task is the lamp", backlog P7)* If Jetzt holds exactly one task, should it be the lamp, one large centred sheet, rather than a column?
2. *(decided 2026-10-20: stays on the board until acknowledged; see DESIGN.md)* On a today-only product, is "Gestern erledigt" on the board the backlog sneaking back in? It could live in review/statistics.
3. *(decided 2026-10-20: yes, with a hover preview; see DESIGN.md)* Should a drop onto a full Jetzt **swap** (current task to Wartet, with undo) instead of refusing?
