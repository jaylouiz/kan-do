# Internationalization (de/en) — Design

**Date:** 2026-10-19 · **Branch:** `feat/i18n` · **Status:** draft for approval

## Intent

kan-do's project rules (CLAUDE.md, `.devin/rules/02, 03, 06, 09, 10, 12, 14, 16`) already require
`const { t } = useI18n()` and "no hardcoded strings in templates", but no i18n layer exists: ~600 UI
strings are hardcoded German, roughly 60 % in templates and 40 % in TS (toasts, menus, table column
definitions, aria-labels, prop defaults, `useHead` titles). This project makes the code match the rules,
adds English as a second locale, and adds guards so the rule stays enforced.

Success = the app renders identically in German (default), renders fully in English when the
environment asks for it, and CI fails on new raw template text or diverging locale files.

## Goals

1. `@nuxtjs/i18n` with locales `de` (default, fallback) and `en`.
2. **No visible language switcher** (user decision). The locale is derived at startup, in this order:
   1. **Dev start parameter** — explicit override for development (see "Locale resolution").
   2. **Persisted locale** from an earlier session.
   3. **Runtime environment** — `navigator.languages` (browser; in Tauri the system WebView reports the
      OS language), first entry whose primary subtag is `de` or `en`.
   4. Fallback `de`.
3. All user-facing copy routed through i18n keys (templates and TS).
4. Locale-aware formatting for dates, numbers, durations, relative labels, plurals.
5. Nuxt UI's built-in strings (and the `UCalendar` in `DatePickerField`) follow the active locale.
6. `<html lang>` follows the active locale at runtime.
7. `useErrorHandler()` / `lib/errorMessages.ts` resolve to locale keys instead of German literals.
8. Enforcement: ESLint `@intlify/vue-i18n/no-raw-text` on `.vue` files + a de/en key-parity check in CI.
9. Shared i18n test helper for unit tests that mount components.
10. ADR `docs/adr/006-i18n-routing-and-locale-detection.md`.

## Non-goals

- Translating **data**: Notion/Todoist status, priority, topic, activity and property values, the
  `TaskStatus` enum, and stored task content stay as they are. Only their *displayed labels* go through
  i18n. The German auto-detect heuristics in the Notion mapping wizard (`StatusMappingStep`,
  `PriorityMappingStep`, `PropertyMapper`) match German *option names in user data*; they stay as-is
  (English heuristics can be added later, not now).
- Sample/seed data (`lib/demo-board.ts`, `plugins/e2e-seed.client.ts`, `tests/e2e/helpers/seed.ts`)
  stays German — it is data, not UI copy.
- Translating dev-only pages: `pages/styleguide.vue`, `pages/error-test.vue`, `pages/dnd-sample.vue`
  (excluded from the lint rule; ~150 strings that no user sees).
- Server API error messages (already English codes; the client maps them).
- Tauri native window title (`src-tauri/tauri.conf.json`), unchanged.
- Unifying the inconsistent German label sets (e.g. board column "Jetzt" vs. status label "In Arbeit" vs.
  context-menu "Heute"). Each existing wording gets its own key so German output does not change.
- Locale-prefixed routes, a language picker UI, RTL, more than two locales.

## Anti-goals (would be a failure even if it "works")

- **Any change to German rendering** other than the intentional fixes listed below. Existing E2E specs
  must pass unchanged; visual-regression baselines should not need updating.
- Logic that branches on translated text (it exists today and must be removed, see "Text-coupled logic").
- English UI that still leaks German strings on reachable screens (board, task detail/add, context
  menu, statistics, settings, Notion setup wizard, welcome/onboarding, sync dialogs, toasts).
- A routing or detection setup that needs a server or cookies to work in the static Tauri build.

## Constraints and decided "how"

### Module and version
- `@nuxtjs/i18n` **10.6.0**, pinned exactly (released 2026-07-30; depends on `@nuxt/kit ^4.5.1`, repo
  runs Nuxt 4.5.2 — compatible). Brings `vue-i18n` 11.x.
- `@intlify/eslint-plugin-vue-i18n` **4.5.1** (supports ESLint 10; repo is on 10.13).

### Routing strategy — `no_prefix`
`ssr: false`, Tauri loads `nuxt generate` output from disk/`tauri://`, so there is no server to redirect
and prefixed routes would add nothing but URL churn and broken deep links. `strategy: 'no_prefix'`.
The module's built-in `detectBrowserLanguage` is **disabled**: it is cookie-based, cookie behaviour in the
Tauri custom-scheme WebView is unreliable, and it cannot express the precedence above. Justification
goes in ADR 006.

### Locale resolution (one client plugin, e.g. `plugins/i18n-locale.client.ts`)
Runs before first render (so no flash of German in English mode). Precedence:

| # | Source | Persisted? | Notes |
|---|--------|-----------|-------|
| 1a | URL query `?lang=de\|en` | yes | Works in browser and in `tauri:dev` (devUrl is localhost). Param is removed from the URL after applying (mirror `?seed` handling). Used by the E2E spec. |
| 1b | Env var `KANDO_LOCALE=de\|en` at start (`KANDO_LOCALE=en npm run dev` / `npm run tauri:dev`) → `runtimeConfig.public.localeOverride` | **no** — forced for that run only, so removing it restores normal behaviour | Applied only when `import.meta.dev` (dev server / `tauri:dev`), so it can never be baked into a production `generate`. |
| 2 | localStorage key `kando-locale` | — | Written by 1a and 3. |
| 3 | `navigator.languages` → first `de*`/`en*` | yes | Persisting is the user's explicit wish ("if there was a language from an earlier session, use this one"). |
| 4 | `de` | yes | |

If both 1a and 1b are present, 1a wins. `?seed=clear` also removes `kando-locale`. Invalid values are
ignored. All storage access wrapped in try/catch.

### Files and keys
- Nuxt 4 default layout: `i18n/i18n.config.ts` (vue-i18n options: `fallbackLocale: 'de'`,
  `datetimeFormats`, `numberFormats`) and `i18n/locales/de.json`, `i18n/locales/en.json` — one file per
  locale, small enough to load eagerly (no lazy loading).
- Keys: dot notation, top-level namespaces by feature area, e.g. `common.*`, `board.*`, `task.*`,
  `taskStatus.*`, `priority.*`, `statistics.*`, `settings.*`, `notion.*`, `sync.*`, `onboarding.*`,
  `errors.*`, `duration.*`, `relative.*`. camelCase leaf names.
- Message syntax is **vue-i18n's** (`{name}` interpolation, `|` plural branches), not ICU — vue-i18n does
  not parse ICU plural syntax. Rule 12 is updated accordingly.
- Raw HTML in messages is not allowed; use `<i18n-t>` with slots.

### Access in code
- Components/composables in setup: `const { t, d, n, locale } = useI18n()`.
- Code outside a component setup (error handler, stores if ever needed): `useNuxtApp().$i18n`.
- Status/priority label maps in `utils/taskStatusMappings.ts` change from `label: 'Offen'` to
  `labelKey: 'taskStatus.open'`; consumers translate. Same for the three duplicated priority label lists —
  consolidate them into one keyed source while keeping each call site's German output identical.

### Formatting
- One shared module (composable, e.g. `useLocaleFormat()`, backed by pure functions taking a locale so
  they're unit-testable) replaces the ~12 copy-pasted duration formatters and every hardcoded `'de-DE'` /
  `localeCompare(…, 'de')`.
- Dates/times: `Intl.DateTimeFormat` with the active locale (or `d()` with named formats). Numbers: `n()`.
- Durations ("45s", "1 h 30 min", "30 min", timebox, "noch …"): **i18n messages with plurals**, not
  `Intl.DurationFormat` (support in older Linux WebKitGTK is not guaranteed). German output must stay
  byte-identical to today's.
- Relative labels ("Gestern erledigt", "Vor 5 Minuten aktualisiert", "Gerade aktualisiert"): i18n plural
  messages so German wording is preserved exactly. English e.g. "Completed yesterday",
  "Updated 5 minutes ago".
- Manual plural ternaries (`Board.vue`, `TopicBreakdown`, `ActivityBreakdown`, `useTimeboxSuggestion`,
  `BoardColumnArchiveSection`) become plural messages.
- Week start stays Monday for both locales (product decision unchanged).
- Duration *parsing* (`utils/common.ts`) is data handling and stays unchanged.

### Nuxt UI locale and `<html lang>`
- `app.vue`: `<UApp :locale="uiLocales[locale]">` with `de`/`en` from `@nuxt/ui/locale`. This also gives
  `UCalendar` the right locale (today it falls back to English — an intentional fix).
- `useHead({ htmlAttrs: { lang: locale } })` reactive in `app.vue`; `APP_LANG` in `nuxt.config.ts` stays
  as the initial static value of the shell HTML.

### Error handling
- `lib/errorMessages.ts`: `getGermanErrorMessage` → returns a **message key** (rename e.g.
  `getErrorMessageKey`); `ERROR_MESSAGES` becomes keys under `errors.*`. The duplicated `ErrorContext`
  union is defined once.
- `useErrorHandler`: toast titles ("Offline", "Fehler", "Fertig", "Warnung") become keys; message is
  translated via `$i18n.t`. The suppression check `includes('synchronisation mit notion fehlgeschlagen')`
  must compare against a key/code, not German text.
- `handleSuccess(message)` / `handleWarning(message)` keep accepting a string; callers pass `t(...)`.
- German errors thrown and later displayed (`TokenStep`, `WizardController`, `add.vue`,
  `useNotionIntegration`, `useTaskOperations` validation) are translated at display time.

### Text-coupled logic to remove
- `TaskStatisticsModal.vue` / `TasksTable.vue`: badge colour chosen by comparing 'Ja'/'Fast'/'Nein'
  → compare on an internal value, translate only for display.
- `TaskProgressCircular.vue`: splits the formatted time on a space → structure the data instead.
- `useStatisticsData.ts`: 'Ohne Thema'/'Ohne Aktivität' used as group keys → internal sentinel key,
  translated at display.
- `useErrorHandler.ts:99` (above).
- `BoardColumn.vue` "?" suffix on empty Waiting headline → part of the message.

### Enforcement
- ESLint: add `@intlify/eslint-plugin-vue-i18n`, rule `@intlify/vue-i18n/no-raw-text: error` on
  `components/**`, `pages/**`, `layouts/**`, `app.vue`; ignore dev pages above. `ignorePattern` for
  pure punctuation/symbols/numbers (e.g. `·`, `—`, `?`, `%`, `/`). Also `no-missing-keys: error` and
  `no-html-messages: error`. The plugin's `settings['vue-i18n'].localeDir` points at `i18n/locales/*.json`.
- Key parity: a Vitest test (runs in CI's `quality` job via `vitest run`) that flattens `de.json` and
  `en.json` and asserts identical key sets **and** identical placeholder names per key, and no empty
  values. Optional `npm run i18n:check` script running just that test.
- Known gap (accepted): `no-raw-text` doesn't see strings in TS; covered by review + the parity test only
  catching missing keys, not literals.

### Testing
- **Shared unit-test helper**: `tests/helpers/i18n.ts` creates a vue-i18n instance with the real
  `de.json`/`en.json`, default `de`. A Vitest `setupFiles` entry registers it globally
  (`config.global.plugins` from `@vue/test-utils`) and provides `useI18n` for the `#imports` mock, so
  existing component tests need no per-file setup. Tests may pass `locale: 'en'` via the helper.
- Unit tests for the formatting module (de and en), locale resolution precedence, and error-key mapping.
  `tests/composables/useErrorHandler.test.ts` updated for the renamed function.
- **E2E default stays German**: `tests/e2e/playwright.config.ts` sets `use.locale: 'de-DE'` — otherwise
  headless Chromium (en-US) would now detect English and break every existing spec.
- **New E2E spec** `tests/e2e/i18n.spec.ts` (local seed via `seedLocalBoard`):
  1. Open `/tasks?lang=en` → column headers are English, `<html lang="en">`.
  2. Reload `/tasks` without param → still English (persisted).
  3. Fresh context with `locale: 'en-US'` and no stored locale → English detected; with `de-DE` → German.
- Existing E2E specs: unchanged.
- Visual regression: should pass unchanged; update baselines only if German rendering changed
  intentionally (e.g. calendar locale), and say so in the PR.

### Rules and docs to update (only where reality differs)

- Fix stale references: `12-i18n.md` → `12-i18n-and-localisation.md` (rules 02, 03, 06);
  `utils/errorMessages.ts` → `lib/errorMessages.ts` (06); `16-acceptance-criteria.md:47`

## Intentional German changes (allowed)
- `UCalendar` renders German month/day names (was English by default).
- `components/ui/InlineEditable.vue` default "Click to edit" becomes a key (German "Zum Bearbeiten klicken").

## Gates before PR
`npm run lint`, `npm run typecheck`, `npm run test`, `npm run test:e2e` green locally; CI green on the PR.
Manual check in `npm run tauri:dev` (default detection and `KANDO_LOCALE=en`) — the builder runs it if the
environment allows, otherwise the PR lists it as an open manual step.

## Calls made by Claude (check these)
- `KANDO_LOCALE` is honoured only in dev builds (`import.meta.dev`).
- Persisting the detected locale (per your "earlier session" rule) means a later OS-language change is not
  picked up until `kando-locale` is cleared (`?seed=clear` or `?lang=`).
- `?lang=` works in production builds too (harmless, and lets E2E run against preview builds).
- Where today's German duration formatters differ from each other ("1 h 30 min" vs "1h 30m"), each
  keeps its own message key so German output stays byte-identical.
- German errors thrown and later displayed become thrown keys/codes, translated where displayed.
- Nuxt UI's built-in strings (e.g. close/aria labels in modals) become German — covered by goal 5.
- Dev-only pages and seed/sample data are not translated.
