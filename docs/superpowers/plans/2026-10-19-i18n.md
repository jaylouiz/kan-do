# Internationalization (de/en) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Route all kan-do UI copy through `@nuxtjs/i18n` with German (default) and English, locale derived from dev override → persisted → environment → `de`, with lint and parity guards.

**Architecture:** `@nuxtjs/i18n` (`no_prefix`, built-in detection off) + one client plugin that resolves and persists the locale. A `lib/i18n.ts` singleton gives non-setup code (`useErrorHandler`, label maps) a `translate()`; components/composables use `useI18n()` from `vue-i18n`. Formatting is consolidated in `utils/localeFormat.ts` + `composables/useLocaleFormat.ts`. String migration proceeds by directory, each task adding keys to both locale files.

**Tech Stack:** Nuxt 4.5 (ssr:false), @nuxtjs/i18n 10.6.0 (vue-i18n 11), Nuxt UI 4 (`@nuxt/ui/locale`), Pinia, Vitest 5 + @vue/test-utils, Playwright, ESLint 10 + @intlify/eslint-plugin-vue-i18n 4.5.1.

**Spec:** `docs/superpowers/specs/2026-10-19-i18n-design.md` — read it before your task; it holds the non-goals, anti-goals and "Calls made" list.

## Global Constraints

- Pin exactly: `"@nuxtjs/i18n": "10.6.0"`, `"@intlify/eslint-plugin-vue-i18n": "4.5.1"` (devDependency).
- Locales: `de` (default + fallback), `en`. Files: `i18n/i18n.config.ts`, `i18n/locales/de.json`, `i18n/locales/en.json`. One file per locale, eager-loaded.
- Strategy `no_prefix`; `detectBrowserLanguage: false`.
- localStorage key `kando-locale`; URL param `lang`; env var `KANDO_LOCALE` → `runtimeConfig.public.localeOverride`, honoured only when `import.meta.dev`.
- **German output must stay byte-identical** except: UCalendar becomes German; `InlineEditable` "Click to edit" → "Zum Bearbeiten klicken"; Nuxt UI built-in strings become German. Existing E2E specs must pass unchanged.
- Do NOT translate data: Notion/Todoist values, `TaskStatus` enum, seed/sample data (`lib/default-tasks.ts`, `plugins/e2e-seed.client.ts`, `tests/e2e/helpers/seed.ts`), German auto-detect heuristics in the Notion mapping wizard, duration *parsing* in `utils/common.ts`.
- Dev-only pages not translated: `pages/styleguide.vue`, `pages/error-test.vue`, `pages/dnd-sample.vue`.
- Keys: dot notation, top-level namespaces `common, board, task, taskStatus, priority, statistics, settings, notion, sync, onboarding, errors, duration, relative`; camelCase leaves. Each distinct existing German wording gets its own key (do not unify "Jetzt"/"In Arbeit"/"Heute").
- vue-i18n message syntax (`{name}`, `a | b` plurals), not ICU. No HTML in messages; use `<i18n-t>` with slots.
- Every key added to `de.json` is added to `en.json` in the same commit, with natural concise UI English.
- In components/composables: `import { useI18n } from 'vue-i18n'` (explicit import, matches the repo's explicit `from 'vue'` style). Outside setup: `translate()` from `~/lib/i18n`.
- No logic may compare against translated text.
- Code/comments/commits in English. Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- After every task: `npm run lint`, `npm run typecheck`, `npm run test` green.

## Review Focus

1. Stored `kando-locale` holds garbage or an unsupported locale (`"fr"`, `""`) → ignored, resolution falls through to detection, then rewritten. (Task 1 tests.)
2. localStorage access throws (private mode / blocked) → locale still resolves, app renders, nothing persisted. (Task 1 tests.)
3. `navigator.languages` empty, undefined, or only unsupported (`['fr-FR']`) → `de`; regional tags (`en-GB`, `de-AT`, `EN-us`) map to base. (Task 1 tests.)
4. Plurals at 0 and 1 in both locales (`0 Aufgaben`/`1 Aufgabe`, `0 tasks`/`1 task`, `1 minute`). (Task 3 tests.)
5. Logic formerly keyed on German text behaves the same in English (statistics accuracy badge colour, "Ohne Thema" grouping, error-toast suppression while Notion is broken). (Tasks 4 and 7 tests.)
