# E2E rules (Playwright: seeding, Notion stub, drag simulation, fixtures)

E2E basics (Local board by default, `seed.ts` helpers, `addInitScript`, the production-build server and its own `PORT`): root `CLAUDE.md` "Testing"; the full text of both is below.

- **E2E seeding detail**: a spec that reloads and must keep its changes passes `{ once: true }` as the last `seedLocalBoard` argument (sessionStorage guard keyed per seed). `fillerTasks(n, status)` pads a column to scroll; `longTitleStackSeed()` is the 3-line-title stack (#282). Read GitHub stub calls filtered (`githubCalls(page, { method, path })`), never by position.
- **Focus overlay off in seeds (#394)**: the Jetzt focus overlay is on by default in the app, but `seedLocalBoard` / `seedNotionBoard` / `seedMixedBoard` and the dev `?seed=` modes write `settings-store` with `focusEnabled: false` (touch specs would lose their first tap, screenshots and contrast checks would see a dimmed board). Opt in with `{ focus: true }` (helpers) or `&focus=1` (`?seed=local&focus=1`); `tests/e2e/focus-overlay.spec.ts` is the model. A spec that writes `board-store` by hand and has a task in Jetzt runs with the overlay on: add `settings-store` there if that matters. The overlay's return timers (2.5 s mouse, 4 s key, 8 s touch) and every other app timer (5 s undo windows, the Jetzt timer) run on the page clock (#543): `installClock(context)` before the seed, then `elapse(page, ms)` / `elapseWindow(page)` from `helpers/clock.ts`; never wait them out in real time, and never `pauseAt` in a touch spec (frozen `Date.now()`, #488). The ticking clock also delays chained timeouts (hydration), so a focus set right after render can be lost: install it only in tests that need a timer, and poll a focus that a keyboard step depends on. `focus-overlay.spec.ts` (`expectOn`) and `stack-delete-gap.spec.ts` are the models. A CSS animation (the timebox nudge's 8 s countdown) is not on the page clock: finish it through `document.getAnimations()` (`timebox-nudge.spec.ts`).
- **App bar helpers (#470, `helpers/appNav.ts`):** the bar and its Mehr panel are driven through `openMore`, `closeMore`, `chooseInMore(row)`, `openSettings`, `openTrash`, `openDayClose`, `resync`, `goToPlace('Heute' | 'Statistik')`; the panel is portalled, so scope to `morePanel(page)` (`more-panel`), never to the bar. `moreButton` has the accessible name "Mehr", or "Mehr, Verbindungsproblem" while a source fails (that name is how specs wait for the settled sync state). At 390px the pages are reached with `showColumnPage(page, 0|1|2)` (`helpers/dnd.ts`, real touch swipes) and read with `activeColumnPage(page)` (`data-mobile-page`); there are no tabs and the pages the bar leads to have no back arrow (a settings sub-page and the welcome steps do, the `setup-back` `BackButton`, #236), so "back" is `goToPlace(page, 'Heute')`. A phone board opens on page 1 while a task sits in Jetzt (kd#191; `SEED_TASKS` has one): a test that needs Offen calls `showColumnPage(page, 0)` first or seeds no Jetzt task.
- **Contrast of a rendered label (#632, `helpers/contrast.ts`)**: `await expectContrast(page, locator, 4.5)` (3 for large text; `measureContrast` returns `{ ratio, foreground, worstBackground }`) hides the glyphs, screenshots the element box and takes the worst ratio over a pixel grid, so it holds through `backdrop-filter`, washes and gradients where axe reports "incomplete" and a DOM walk of backgrounds is blind (#615). Point it at the text element (the outer 15 % of its box is skipped, the rest sampled on a 20x20 grid). It cuts every transition on the page and hides descendants' glyphs itself (the 150 ms colour transition, `color(srgb …)` computed values and label alpha are handled); wait for a fading surface to be shown and at rest first (`settleAnimations`). Chromium only for blur (WebKit never paints `backdrop-filter`). Axe stays the page-wide scan; model: `a11y.spec.ts` "app bar labels over scrolled cards". Never rebuild this per issue.
- **Waiting**: wait for the element or state the next line needs (`await expect(locator).toBeVisible()`, `locator.waitFor()`, `page.waitForResponse()` for one request, `expect.poll` for stored state); `waitForLoadState('networkidle')` and `waitUntil: 'networkidle'` are ESLint errors (#546: 500 ms of silence per call, and a flake when a background request lands in the window).
- **Gate failure that passes solo** is a load race: reproduce with `--repeat-each=12 --workers=6` before changing anything (a toast measured mid-slide, a refused Notion sync marking the source broken before the save; run_de2a3728622f cost 25 min).
- **Drag-and-drop**: in E2E tests use `page.mouse` simulation (`locator.dragTo()` and `DragEvent` are ESLint errors). Pattern: `docs/testing/e2e-dnd-patterns.md`.
- Fixture data in `tests/fixtures/notion/`
- **Notion stub**: server-side, activated by `E2E_NOTION_STUB=1` env var **or** sentinel token `notion_test_stub` in `notionConfig.token`. `tests/e2e/playwright.config.ts` sets `E2E_NOTION_STUB=1` by default. The stub keeps in-memory page state per token: writes (`update-task`, `tasks` PATCH) show up in later page retrieves and data-source queries. `seedNotionBoard` uses a unique `notion_test_stub:<uuid>` token per test (accepted like the sentinel), so state never leaks between tests; its defaults match the fixture ids `db-123`/`ds-123`. A `fail=<status>` stub token fails every Notion route (error paths), `create-fail=<status>` only `create-task`; `pages=<n>` pads the session to n pages (cap 2000) and `query-data-source` pages them like Notion (`page_size`, `start_cursor`, `has_more`). `NotionClientAPI.queryDataSource` follows the cursor (ceiling 100 pages, any failure throws), so a stub board with >100 tasks needs no special handling. Real Notion without user clicks: the `notion-sandbox` skill.
- **No `/_nuxt/` imports (#540)**: that path only exists under Vite dev, so a spec never `import()`s app source in `page.evaluate`. `window.useNuxtApp()` (Pinia, router) works in every build. For a composable, `plugins/e2e-seed.client.ts` hands out `window.__kandoE2E.connectSource(id)` (runs in the Nuxt context like the Verbindungen page's call); it exists wherever `__NOTION_STUB_ALLOWED__` is true (dev, Vercel preview, a build with `NOTION_STUB_ENABLED=true`) and is tree-shaken from real production. A new hook goes next to it, listed here.
- **Production-build server (#541)**: `tests/e2e/playwright.config.ts` runs `scripts/e2e-server.mjs` as `webServer`: `nuxt build` with `NITRO_PRESET=node-server`, `NOTION_STUB_ENABLED=true` (so `__NOTION_STUB_ALLOWED__` stays true in the bundle and the sentinel tokens work) and `KANDO_E2E_BUILD_DIR=.e2e-build/<port>` (`nuxt.config.ts` sends `buildDir` and `nitro.output.dir` there), then imports the Nitro entry with `E2E_NOTION_STUB=1` and the cwd at the repo root (`notionStub.ts` reads `tests/fixtures/notion` from the cwd; Playwright starts `webServer` in `tests/e2e`). The build output is quiet unless it fails, and the directory is removed when the server stops. Specs run against minified code and built chunks, so nothing may rely on dev-only behaviour (`/_nuxt/` imports, below; `import.meta.dev` branches). `BASE_URL` skips the whole thing and targets any running server.
- **Cold-server warm-up**: `tests/e2e/global-setup.ts` loads `/tasks?seed=local` once before the specs (also with `BASE_URL`). Against the build it is one cheap page load; it matters for `BASE_URL` against `nuxt dev`, where Vite compiles lazily and the first specs timed out (#219).

Notion stub by hand (no real credentials needed):
```bash
# Option A — env var (applied server-wide; test:e2e builds with it by default):
npm run dev:e2e
BASE_URL=http://localhost:3000 npm run test:e2e   # the same suite against the dev server

# Option B — sentinel token (per-request, no env var):
# seed notionConfig.token = 'notion_test_stub' in localStorage, or use ?seed=notion:
npm run dev:e2e
# open http://localhost:3000/tasks?seed=notion
```

## A new spec or a new 390 viewport

`tests/scripts/e2e-gate.test.ts` treats every spec that names a 390 viewport as a phone spec: it must be listed in the app-shell rule of `.claude/hooks/e2e-gate.json`, and a new or deleted spec file needs its `map` entry. Prefer extending a mapped spec over a new spec file.

## CI-only (Linux) failures

Reproduce in Linux Chromium before guessing (kd#100): `colima start`, then run the spec in `mcr.microsoft.com/playwright:v<the repo's @playwright/test version>-noble` against a server on the host (`BASE_URL=http://host.docker.internal:<port>`); mount the worktree from under `$HOME` (colima does not share `/private/tmp`). `--cpus 1` exposes focus and timing races CI hits.

A sideways-scroll flake (about 1 in 12 runs) is timing-dependent, so element boxes can look fine: probe the scroll position with a deterministic `window.scrollTo(15, 0)` and assert `scrollX` stays 0 (kd#269). Never size layout in `100vw`: a classic scroll bar on Linux makes it wider than the layout.

## Seed modes

Local tasks (default for UI-only tests, no stub needed): `npm run dev`, open `http://localhost:3000/tasks?seed=local` (board pre-loaded with test tasks). Notion stub (no real credentials): `npm run dev:e2e`, open `/tasks?seed=notion`. After pulling a Playwright upgrade: `npx playwright install chromium`.

The `?seed=<mode>` URL param (handled by `plugins/e2e-seed.client.ts`) writes the correct localStorage state and reloads. Supported modes: `local`, `dayclose` (board tailored to review the end-of-day sheet; `&alldone=1` leaves nothing open), `notion`, `newday` / `newday-all` (first start on a new day, the recap opens; `&daysago=n`; E2E: `seedNewDayBoard`), `demo` (the realistic demo board of #527, `lib/demo-board.ts`, also the onboarding sample button: a landscaping business owner's tasks with stacks under every grouping option, a Jetzt timebox, Wartet notes, carry-over and done-today tasks; for trying the app and reviewing UI, never an E2E fixture, specs use `local`), `mixed` (Local and Notion tasks side by side, Notion stub, `&default=local` makes Local the default source; E2E: `seedMixedBoard`), `clear`.

## E2E server

**E2E server**: `npm run test:e2e` starts `scripts/e2e-server.mjs` (build, then serve a production build on `PORT`, default 3000; the pre-merge gate and `npm run release` run the same command). Playwright reuses whatever already serves that port, so in a worktree, or next to a dev server on `:3000`, use `PORT=<free port> npm run test:e2e …`. The build has its own `.nuxt`/output below `.e2e-build/<port>`, so it never touches a running dev server, `.nuxt` or the `.output` of `npm run generate`; a fresh worktree needs no setup (the script runs `nuxt prepare` when `.nuxt` is missing; lint/typecheck still need it by hand: `npx nuxt prepare`). Stop your own server only by its port's PID (`lsof -ti tcp:<port> -sTCP:LISTEN | xargs kill`). Debugging against `nuxt dev`: `BASE_URL=http://localhost:<port> npm run test:e2e …` (no build; the visual shots then differ by ~1 px).
