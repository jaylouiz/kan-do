# Pre-merge E2E gate

The pre-merge hook `.claude/hooks/e2e-before-merge.sh` picks a tier per PR (`scripts/e2e-gate.mjs`, rules in `.claude/hooks/e2e-gate.json`): docs-only and style-only PRs (every file a `.css`, a `.vue` change inside `<style>` or comments, docs or a snapshot, decided from the diff against the merge base; #375) skip E2E, only their changed specs run, plus the `design` specs (rendered Impeccable scan `design-detect`, ARIA state snapshots `state-structure`) when a file lies on a `design` path (a style change is what they judge); any other PR runs a smoke set plus the specs mapped to its files (risk areas have their own `map` rules, `area` says why), the specs importing a changed `tests/e2e/helpers/` file, the specs whose text contains a changed i18n value or `data-testid` (#525), the specs it touches and the ones on its `E2E-specs:` line. No glob and no label selects the whole suite (#446): only `E2E_GATE=full` in the hook's environment does (manual override; `npm run release` runs the full suite itself), plus the fail-safe of an unresolved or ≥100-file list. Testing mode (#693, `.claude/testing-mode`, `fast` or `quality`, default `quality`): in `fast` the non-skip result is tier `fast` = smoke + the `map` rules flagged `risk: true` + touched specs and helper importers + the `E2E-specs:` line; the `design` specs and the label/testid matches are dropped, except the style fingerprint (kd#230: the `catalog` rule adds `ui-catalog` for a changed stylesheet or asset, `app.config.ts`, `nuxt.config.ts` or a `.vue` file of a component that has a `catalog/` entry; a style-only PR then runs just that spec), and any other style-only PR runs no E2E. Mark a new rule `risk: true` when its area is in the profile's "Risk areas". Runs retry once (`--retries=1`; a test that passes only on retry is printed as `flaky:`), a `<sha>.<tier>` stamp makes an unchanged head run once. GitHub CI reuses this selection on PRs (`scripts/ci-e2e-plan.mjs`, kd#187): its CLI calls `scripts/e2e-gate.mjs` with the PR's files, body and head and runs the listed specs over `ceil(specs / 12)` shards (at most 8); a PR that changes the workflow, the plan or gate script, the E2E server, the Playwright config or the package files forces `E2E_GATE=full`; every other event runs the full suite. A change to the gate's output shape (`tier`, `specs`) must keep the plan's tests green (`tests/scripts/ci-e2e-plan.test.ts`).

The hook gates this repository only (kd#205): a merge that names another repository (`-R/--repo`, a full PR URL, the REST path `repos/<owner>/<repo>/pulls/<n>/merge`, `GH_REPO`) passes untouched, because that repository has its own merge rule. "This repository" is the `origin` of `CLAUDE_PROJECT_DIR`; a PR URL wins over `-R` (as in gh), a merge that names no repository resolves as before, and anything that does not read as a literal `[HOST/]OWNER/REPO` (a variable, no origin) stays gated or is refused. The tests pose as a checkout through `project(repo)` in `tests/scripts/e2e-before-merge-hook.test.ts`.
