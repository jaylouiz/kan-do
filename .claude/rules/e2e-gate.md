# Pre-merge E2E gate

The pre-merge hook `.claude/hooks/e2e-before-merge.sh` picks a tier per PR (`scripts/e2e-gate.mjs`, rules in `.claude/hooks/e2e-gate.json`): docs-only PRs skip E2E (unit-test files below `tests/` count as docs here, #902; `tests/e2e/` and `tests/fixtures/notion/` do not); style-only PRs (every file a `.css`, a `.vue` change inside `<style>` or comments, docs or a snapshot, decided from the diff against the merge base; #375) run only their changed specs, the specs of the `E2E-specs:` line and the screenshots (#684: `visual.specs`, `visual-regression`, for a stylesheet or `<style>` change on a `visual.paths` UI path; a changed baseline `tests/e2e/snapshots/<name>.spec.ts/*` selects `<name>` in every tier), plus the `design` specs (rendered Impeccable scan `design-detect`, ARIA state snapshots `state-structure`) when a file lies on a `design` path (a style change is what they judge); any other PR runs a smoke set plus the specs mapped to its files (risk areas have their own `map` rules, `area` says why), the specs importing a changed `tests/e2e/helpers/` file, the specs whose text contains a changed i18n value or `data-testid` (#525), the specs it touches and the ones on its `E2E-specs:` line. No glob and no label selects the whole suite (#446): only `E2E_GATE=full` in the hook's environment does (manual override; `npm run release` runs the full suite itself), plus the fail-safe of an unresolved or ≥100-file list. Testing mode (#693, `.claude/testing-mode`, `fast` or `quality`, default `quality`): in `fast` the non-skip result is tier `fast` = smoke + the `map` rules flagged `risk: true` + the specs a non-risk rule keeps in its `fast` list (#684: `visual-regression` on the board, task, ui, layout, timer and css rules) + touched specs and helper importers + the `E2E-specs:` line; the `design` specs and the label/testid matches are dropped, except the style fingerprint (kd#230: the `catalog` rule adds `ui-catalog` for a changed stylesheet, `app.config.ts` or a `.vue` file of a component that has a `catalog/` entry; a style-only PR then runs just that spec), and a style-only PR outside `visual.paths` runs no E2E. Mark a new rule `risk: true` when its area is in the profile's "Risk areas". A rule that is not `risk` still needs `fast: [...]` for a spec that measures the rendered page across areas (`phone-hit-areas`, `motion-guard`, `visual-regression`): without it a `fast` PR never runs it (#818, #820 went red on main). Runs retry once (`--retries=1`; a test that passes only on retry is printed as `flaky:`), a `<sha>.<tier>` stamp makes an unchanged head run once. GitHub CI reuses this selection on PRs (`scripts/ci-e2e-plan.mjs`, kd#187): its CLI calls `scripts/e2e-gate.mjs` with the PR's files, body and head and runs the listed specs over `ceil(specs / 12)` shards (at most 8); a PR that changes the workflow, the plan or gate script, the E2E server, the Playwright config or the package files forces `E2E_GATE=full`; every other event runs the full suite. A change to the gate's output shape (`tier`, `specs`) must keep the plan's tests green (`tests/scripts/ci-e2e-plan.test.ts`).

The hook gates this repository only (kd#205): a merge that names another repository (`-R/--repo`, a full PR URL, the REST path `repos/<owner>/<repo>/pulls/<n>/merge`, `GH_REPO`) passes untouched, because that repository has its own merge rule. "This repository" is the `origin` of `CLAUDE_PROJECT_DIR`; a PR URL wins over `-R` (as in gh), a merge that names no repository resolves as before, and anything that does not read as a literal `[HOST/]OWNER/REPO` (a variable, no origin) stays gated or is refused. The tests pose as a checkout through `project(repo)` in `tests/scripts/e2e-before-merge-hook.test.ts`.

The hook serves the run on a port from `.claude/hooks/e2e-port.sh` (3200-3899, skipping Chromium's blocked ports such as 3659 and ports already listening, #349).

One gate run per machine (#830): the hook takes a lock in the git common dir (`kando-e2e-gate.lock/`, shared by every worktree) before Playwright starts; a second merge waits up to `E2E_GATE_LOCK_WAIT_SECONDS` (default 300 s, at most half the hook timeout), then blocks as `GATE BUSY` (checks.tsv result `busy`, no run, nothing failed) naming the holder's PR; retry it when that run ends. A lock whose owner process is gone (PID dead, or reused by another process: the owner file keeps the start time) is taken over. Lock wait and run stay a minute below the hook timeout (`HOOK_TIMEOUT` in the hook equals the `timeout` in `.claude/settings.json`; a test checks). The run adds `scripts/e2e-gate-reporter.mjs` to `--reporter`, which records each test that ended as expected in `kando-e2e-pass/<sha>.<key>.progress`; after a timeout or a failure the next run of the same head and spec list runs only the spec files not yet passed (`run-args` in `scripts/e2e-gate.mjs`, from the hook's own checkout), and a pass removes the progress. The checks.tsv row of a resumed run counts the spec files it ran.

`visual-regression.spec.ts` is skipped in CI (macOS-rendered baselines, `test.skip` on `CI`), so a green CI run says nothing about it; the local gate runs it in both modes for board, task and shared UI changes, style-only PRs and changed baselines (#684: #676 merged with stale baselines, #682, because `fast` dropped the non-risk rules and the style tier never selected it). A new non-risk map rule that lists it needs `fast: ["visual-regression"]` (a test checks). A UI PR that moves visible pixels still runs the spec on its own and commits the regenerated PNGs.
