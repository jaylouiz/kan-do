# New day: persisted fields (#356, #387)

Split from `.claude/rules/persistence.md` (#901), which holds the general persistence rules (`appStorage`, `PERSISTED_KEYS`, `afterHydrate`).

- **New day (#356, #387):** `day-recap-store` holds `lastNewDay` (the day the user last started fresh, or the baseline; monotonic like `lastShownDay`; before #387 the day the automatic pass ran; data without it, i.e. from before #356, gets its baseline from the first day check, never at hydration: today, or the day of `lastShownDay` when that is earlier, so "due" never hangs on the recap's marker, which leaving the recap moves), `sentBack` (`{ day, ids, waiting?, from? }`, the Jetzt and Offen tasks of that day's fresh start: the group of that one day; `waiting` is optional, the Wartet tasks that start or day close took off: the block on "Alle" and the morning's recap read it for that one day (#469; data from before it has none and lists no Wartet task in the block); `from` is optional too (#741), the local day the tasks are from, which titles the block ("Von gestern", "Von {weekday}", "Vom {date}"): a fresh start writes the marker it replaces (the day the board was last planned), a day close its own day, none without tasks; absent, malformed or not before `day` reads as the day before (`sanitizeSentBack`, `blockWhen` in `utils/recapDay.ts`)), `noticeClosedDay` (the day the notice that offers the fresh start was closed) and `timeOffer` (the same shape as `afterMidnight`: the question "Zeit abziehen / Zeit behalten" the day check leaves; shown that day only, cleared when answered, replaced by a later one); `tasks-store` holds `afterMidnight` (`{ taskId, day, seconds, spans }`, what a Jetzt timer counted after the midnight it ran across while the user was away from the window, D3 o, and the wall-clock `spans` of it, which the user's "Zeit abziehen" also cuts out of `taskStatistics.workSessions`, D3 h). The day close (#480) does the fresh start's work in the evening through the same take-off (`composables/useTakeOffBoard.ts`) and writes `lastNewDay` and `sentBack` for the next local day (`dayRecap.markDayClosed(nextDay, ids)`: monotonic, a second close the same evening adds its ids, a day before the stored marker writes nothing), so `lastNewDay` can be one day ahead of the clock; the next morning is then not due (no notice, no second fresh start) and the group of `sentBack.day === today` shows. The board day count is not taken back at close. `planNoteSeen` (#711, boolean) is the one-time note on "Alle" after "Neuen Tag planen" answered (closed, or the user went on to "Heute"): once per user, additive (nothing stored reads as not seen, only a literal `true` is seen: `validPlanNoteSeen`, no write at hydration; the arrival that shows the note is runtime only, `planArrival` in `lib/dayBegun.ts`, armed by `useNewDay().freshStart()` / `armPlanNote()`, never stored). It travels in the `day-recap-store` blob, so export/import and the app reset carry it. No new top-level field. All additive: older data has none, readers go through `validLastNewDay` / `validSentBack` / `validNoticeClosedDay` / `validTimeOffer` / `validAfterMidnight` (malformed reads as none, so no start is repeated and no time is ever removed for it), nothing writes at hydration, and no card moves at hydration. `firstBackDay` and `backNoteClosed` (the one-time note of #356) are no longer read or written: a stored value is ignored; so is a stored `board-store.notPlannedFromWaiting` (#516: it loads without error, is not kept in memory and is left out of the next persist). Tests: `tests/store/dayRecap.test.ts`, `tests/composables/useNewDay.test.ts`, `tests/store/boardNotPlannedOrder.test.ts`, `tests/store/tasks.afterMidnight.test.ts`
