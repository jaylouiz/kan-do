# Orchestration (issue-workflow profile partial)

<!-- Full text of the profile section "Orchestration" (`.claude/issue-workflow.md`); read when: Orchestrate (coordinator), merging a PR yourself. -->

- runner: Orca; max 5 concurrent workers (user decision: dev-server ports, Playwright CPU, shared visual baselines). Ports, risk globs, verify/build, after-merge steps, deploy check and the PR-body check: `.claude/issue-workflow.sh` (read by `spec.sh`, `merge-pr.sh`, `guard.sh`)
- with 3+ workers: specs say E2E `--workers=2`; the hook retries a failing test once itself; after a hook failure in specs the PR does not touch, rerun them alone once more (`PORT=<free> npx playwright test <failed files>`); many first-render timeouts mean load (`uptime`), not the PR; at load above ~20 run only the touched and mapped specs, never the whole suite (a 65-spec run never progressed, 25 min, #593; sibling sweep PRs ran 12-15 min mapped runs): the gate runs the rest
- a PR branched before a merged test-infra fix rebases first; parallel epic siblings never fix an ADR number in the spec (the later-merged PR renumbers); parallel siblings do not edit shared status docs (`docs/design/redesign-plan.md`, ratchet baselines): the lead names the step in the PR body and the last sibling to merge updates the doc (plan.md conflict, run_65c33ded05be)
- serialize: issues touching the same risk area or the same file; only the first PR changing a PNG in `tests/e2e/snapshots/` regenerates it, the next waits, rebases, regenerates
- merge gate: the `PreToolUse` hook `.claude/hooks/e2e-before-merge.sh` runs the tiered E2E gate on `gh pr merge`. `E2E_GATE=full gh pr merge <pr> --merge` only when the PR changes gate logic (`e2e-*.sh`, `e2e-*.pl`, `scripts/e2e-gate.mjs`, a new or changed rule in `.claude/hooks/e2e-gate.json`; a path added to an existing rule is a normal targeted PR) or shared test infrastructure beyond a helper. A flake fix runs its spec through the gate like any changed spec; the fixer proves it with `--repeat-each=30 --retries=0` and states it in the PR. "Checks pass" = `merge-pr.sh prep` (verify, build when needed) + the hook's E2E run; no host builds a PR branch. **Never wait for PR CI** (owner decision 2026-11-12, alpha phase): a PR runs only `quality` there (lint, typecheck, Vitest; no E2E), and a PR merges once the local gate is green, risk areas and CI changes included. One gate run per machine (#830): a merge whose gate finds another gate running waits up to 5 min, then blocks as `GATE BUSY` without running: merge the next PR meanwhile and retry it after that run ends; a gate that timed out or failed keeps the spec files that passed, so retrying the same head runs only the rest. Do not merge while a flake lead stress-tests (load 65 timed the gate out, run_69d92df57b4a), and judge a flaky-looking gate failure by repeating the spec on `main` and on the PR (`--repeat-each`), never by one alone-run. The full E2E suite runs on every push to `main` (CLAUDE.md "CI") and by hand (`gh workflow run ci.yml`); `npm run release` runs it locally. A red `main` after a merge (the full run) gets an `inbox` issue naming the missing `map` rule. The coordinator runs `gh run list --branch main --limit 3` at wave start and after each merge or direct push (a red run from a direct push went unseen for a wave, run_a03192da00c8).
- Notion-touching PRs: the builder (and fixer) runs `npm run test:contract` in its worktree and reports the result in the PR; a failure blocks the merge. `.claude/settings.json` allows it and `npm run notion:sandbox *`; run them as a plain command (no `cd … &&` prefix) so the allow rule matches. One contract run at a time (all share one sandbox token; parallel runs 429 each other, #539 lost 6 min): `pgrep -fl test:contract` first. If a worker is still denied, the coordinator runs it before merge
- CI reruns (run_c70ac44813db): `ci.yml` cancels in progress per ref, so `gh run rerun` on an older run of a PR cancels the newer head's run (~35 min lost, kd#125); rerun only the latest run of the head, or push a new head. `gh pr update-branch` diverges the worktree (prep's push is then rejected): `git pull --ff-only` in the worktree first. The CI e2e job is a matrix of up to 8 shards (`e2e (n/total)`, kd#129, kd#187), only as many as the selected specs need.
- merging a standalone build PR yourself (the user says "until merged"): `merge-pr.sh prep <pr>` first; it needs a `## Review` section in the body (`route: lead|reviewer`, `by: <who>`, findings; check with `merge-pr.sh review-check <body file>`), then `gh pr merge`, then `merge-pr.sh after <pr> "<summary>"`
- after merge: `merge-pr.sh after` (fast-forward of the main checkout when on `main`, `npx npm@11.19.0 install` when `package.json` changed, `cleanup-merged.sh`, deploy check); a deploy that is not green gets an `inbox` issue
