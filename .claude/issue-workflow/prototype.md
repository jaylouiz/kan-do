- host: `PORT=<port> npm run dev`, then `/tasks?seed=local&variant=<key>` (ready when the log shows `Ready in`; never `curl` a redirecting route; seed and variant in one URL: a later `goto` without `seed` shows onboarding); variants mount inside the existing page (board, task sheet, settings page). A new top-level surface gets a route under `pages/prototype/`.
- switcher: `components/prototype/PrototypeSwitcher.vue`, a fixed bottom pill (← key label →, arrow keys outside inputs) that updates `?variant=`. Nuxt names components in that folder `Prototype<Name>`: other proto-only components live outside it or are used by the prefixed name. It is not on `main` as a component: copy the generic `.claude/templates/PrototypeSwitcher.vue.template` there and edit only its `GROUPS` map (one group per independent question: a single issue keeps the `variant` group, a design batch adds a group with its own query key per further issue, e.g. `&v162=a`; up and down pick the group, left and right its variant) (other proto branches hardwire their own variants and plugins).
- branch: `proto/<n>-<slug>`, own worktree, never PR'd or merged; pushed per round as the record.
- cleanup: `.claude/hooks/cleanup-merged.sh` removes the local worktree, local branch and `origin/proto/<n>-*` once issue #<n> is closed and no open issue names the branch in its body (a prototype shared by a design batch stays until the last of its issues closes; dirty worktrees skipped); while it is open the branch stays as the Design record.
- proto CSS sits outside `@layer`, so it beats Tailwind utilities too (`max-md:hidden` loses to a proto `display:flex`): switch proto layouts with media queries in the proto CSS, not with utilities
- relaxed: `.claude/hooks/verify.sh` and `eslint-file.sh` skip `proto/*`, so raw German strings, missing tests and lint warnings are fine. Keep `nuxt build` working (the round's production-build check builds it).
- share: a pushed `proto/*` branch builds a gated Worker Preview (ADR 021 "Prototype previews"); `wf_proto_preview_url <branch>` (`.claude/issue-workflow.sh`) prints its URL once Workers Builds built the pushed head (a few minutes; run it with a 10-minute Bash timeout), else fails: then the local link is the only one. The round's `Preview:` is that URL plus route, seed and variant; the user adds the gate token once per preview host (never an agent). Anyone else runs the branch locally; an agent checks on a production build (`PORT=<port> node scripts/e2e-server.mjs`, own build dir, safe beside the coordinator's dev server). Seed URLs work on both because the web build uses `localStorage`.
- agent checks of a prototype: one dev server per directory (Nuxt's dev lock), so iterate on the coordinator's server read-only; every round's check includes one real pointer click on the switcher (keys and URLs missed a dead pill, #347); a page reachable by two paths through a vue-router alias needs `navigateTo(..., { force: true })`, else the move is a silent redundant navigation; restart the dev server before each screenshot batch and after the first stale reading (stale HMR cost 12 and 8 min, #705 #707), and check the port is free after stopping one (#703; `nuxt dev` leaves a parent process, so also `pgrep -f 'nuxt dev'` for the own worktree and kill it, #374); stale HMR came back after the fix (#725, 8 min): shoot screenshot batches from a production build (`PORT=<port> node scripts/e2e-server.mjs`) once a restart still reads stale
- look (Build's Look comment, `ux-impact` issues): PR branches get no preview (only `proto/*` does), so `Preview:` is the public instance `https://kando.julius-wuestefeld.workers.dev` (gated while the secret launch lasts: the user's browser has the gate cookie; Workers Builds deploys `main`, `wf_deploy_check` reads its check run) followed by `Path:`, marked "valid once merged and deployed". The Look is taken after Done, on Production.
- data: local seed only; no Notion, Todoist or GitHub calls.
