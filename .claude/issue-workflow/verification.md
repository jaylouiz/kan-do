- **testing mode** (#693): `.claude/testing-mode` holds `fast` or `quality` (default and fallback `quality`); read it before writing tests or choosing checks. `quality` = everything below. `fast` (pre-stable; switching modes is a one-way item, see "Decisions"):
  - write a test only for (1) a bug fix (regression test that fails without the fix), (2) logic with a branch, loop, parser, money or security, (3) anything in "Risk areas"; none for pure markup, copy or styling, and no new visual baselines or ARIA snapshots outside a risk area. Existing tests stay, and a spec, baseline or ARIA snapshot the diff breaks (a moved page, a changed link or label) is updated in the same PR: fast trims new tests, never repairs (run_d0fe7191bd61: #691 cost 2 fix rounds).
  - Stop hook and pre-push hook (`.githooks/pre-push`): `lint:ci`, `typecheck`, `design:detect` and `vitest run --changed origin/main` (Stop: no rendered design scan); GitHub CI selects per event (CLAUDE.md "CI"), never by testing mode; pre-merge gate tier `fast` (smoke + risk-area `map` rules flagged `risk: true` + touched specs + the `E2E-specs:` line; no `design` specs but the style fingerprint `ui-catalog` for a stylesheet, `app.config.ts` or catalogued-component change (kd#230), no label/testid matches; docs and other style-only skip as before); spec sizing: Specify's Verification section follows the same rule.
  - platforms and browsers: `fast` verifies desktop (Tauri) behaviour on macOS only and web behaviour in Chromium only; a new check, spec project or CI matrix entry for another OS or browser (Windows, Linux desktop, WebKit, Firefox) is `quality`-only. Today the project has none, so the two modes differ in depth, not in platform coverage (the Linux CI container is the one other environment: Chromium, the full suite on `main`).
  - never reduced in either mode: `npm run verify` as a manual command, the Notion contract test for Notion PRs, the guard hooks. Releases: `alpha`/`beta` follow the mode, `stable` always runs full verify + full E2E and refuses `fast` (`docs/release.md`).
- rendered design scan and visual baselines run only through `PORT=<port> npm run test:e2e` (production build), never against `nuxt dev` (sandboxed localStorage script error, dep-optimize loop: 8 min, #469); the same holds for hit-area probes and before/after screenshots: a worktree dev server keeps stale `app.config.ts`/CSS and ignores reverts (50 min in two leads, #590 #592; a phone hit-area spec green on dev was red in CI), so shoot one production build per state. A change that moves a persistent shared element (app bar, task sheet shell) also runs `visual-regression` before READY: the fast tier skips it and the full gate then fails on stale baselines (#519, 25 min)
- gate command: `npm run verify` (lint:ci, typecheck, vitest; the Stop hook runs the same); a lead that changes UI classes or components also runs `npx vitest run tests/config` before READY (`--changed` misses the ratchet and lock-in tests, #638)
- a new regression test must fail with the fix reverted (check once: `git diff HEAD -- <src paths> > <scratchpad>/fix.patch && git apply -R <scratchpad>/fix.patch`, run the test, `git apply <scratchpad>/fix.patch`; list paths inline, zsh does not word-split `$VAR`; on macOS `sed -i` needs `''`)
- never commit absolute `/tmp` or scratchpad paths (e.g. a debug `page.screenshot({ path })`)
- a spec that changes existing behaviour: `rg` the old behaviour's wording in doc comments and types too (#304)
- waiting on an E2E run: never `pgrep -f 'playwright test'` in a monitor loop (it matches its own shell, 25 min lost); write `[p]laywright` or read the task output file
- E2E: `PORT=<free port> npm run test:e2e -- tests/e2e/<name>.spec.ts` (full paths: a bare word is a substring filter; zsh does not word-split `$SPECS`: pass a list as `${=SPECS}` or an array). List the specs you ran as `E2E-specs: a b c` (basenames) in the PR body; the pre-merge hook adds them to its tier. `npm run build` when the PR touches build config (`nuxt.config.ts`, `package.json`, `app.config.ts`, `server/`); a `nuxt.config.ts` change also runs `smoke` and `visual-regression` (E2E runs against the built app since #541: a dev-only check misses what the build drops, #576; a build-tooling spike, e.g. a PostCSS or Vite plugin, also proves itself with `npm run build`, kd#70)
- gate tier before READY: once the PR exists, run `gh pr view <pr> --json files,body,baseRefName,headRefOid | node scripts/e2e-gate.mjs` and run what its `tier` says (`full` = `PORT=<free> npm run test:e2e` once, report the counts; a baseline-heavy or 100+ file diff lands there); `wf_pr_body_check` now refuses a PR body whose `E2E-specs:` line misses a spec the gate selects for the diff (#699), so run and list them all; `READY` names the tier; when a sibling PR merged since the last rebase (`git fetch`, `gh pr view <pr> --json mergeStateStatus`), merge `origin/main` and rerun the touched specs first: shared specs, seeds, `e2e-gate.json` and `terms.json` conflict, and a separate fix worker costs ~15 min (run af99fcba, PRs 406, 407); rerun the tier command after that merge, since moved baseline PNGs flip route lead to reviewer (#574, run_a03192da00c8)
- terms: an agent never sets a term `decided` (guard hook: only the user's `npm run terms:approve` writes `terms.lock.json`); new terms stay `proposed`, the PR body lists them as waiting, and the coordinator hands the user the approve command only after the PR is merged (ids exist on main then)
- DnD spec set (drag changes): the specs of the `drag-and-drop and stacks` rule in `.claude/hooks/e2e-gate.json` (the gate runs the same set; list it with `echo '{"files":[{"path":"composables/useBoardDndKit.ts"}]}' | node scripts/e2e-gate.mjs`, field `specs`, then `npm run test:e2e -- $(printf 'tests/e2e/%s.spec.ts ' <names>)`)
- repeat-run command: `PORT=<free> npx playwright test -c tests/e2e/playwright.config.ts <file> --repeat-each=<n> --retries=0 --workers=4` (`--workers=1` for timing), on a production build: 10 runs for a new timing test, 30 as the flake proof (#446, replaces the `e2e-full` label), result in the PR body; a flaky or red run of any check is reported with its first error line, never just "failed once" (#544 lost 15 min re-measuring a cause nobody had written down); a pattern sweep over several specs (no single flaky spec) runs `--repeat-each=5` per changed spec A red-main test is a flake only after `--repeat-each 5` at low load passes at least once; 5/5 red is deterministic (#750).
- a flake whose log shows only the assertion: read the failed test's `error-context.md` first (page snapshot at the failure, e.g. an empty palette, #572); the console is in the failed test's `trace.zip` (`test-results/*/`; the `*.trace` JSONL holds console events); a race on the first fetch reproduces by delaying the stub route (`page.route` + wait), not by `--repeat-each`; a focus or timing race reproduces under load against one persistent server (`node scripts/e2e-server.mjs` + `BASE_URL`, `--workers=10 --repeat-each=60`: ~5 % in 35 s, #685)
- a global CSS change (scroll bars, root layout) runs `visual-regression.spec.ts` once in Specify with the candidate CSS injected, in the default headless mode, before choosing the approach (#669: a forced-classic-bar check hid ~40 moved baselines)
- any change visible on the board (headers, cards, stacks) or in a shared UI component (the setup flow, dialogs several views use) also runs `visual-regression.spec.ts` before the PR (#564: the merge gate caught it, 20 min); update snapshots only for intended changes; which region a baseline moved: `magick compare -metric AE old.png new.png diff.png` and `magick diff.png -trim info:` for the box (no PNG reader in the repo)
- motion changes (#578): a production build, never `nuxt dev` (stale composables and CSS cost two leads 37 min, #610 #648): `npm run build`, `PORT=<free> npm run preview:e2e`, then `npm run motion:film -- --out <scratchpad dir> --base http://localhost:<port> [--group topic|priority]` (`scripts/motion-film.mts`: seeks the paused script animations to 12 points, writes a filmstrip per stack and flags jumps, pops and endpoint mismatches; exit 1 on a flag). Never in `test:e2e` or the gate. A motion change also runs `tests/e2e/motion-guard.spec.ts` on the production build before READY: main CI (Linux) failed it for 4 merges while macOS passed (#666, #671). Real-device feel stays manual: Chrome DevTools Performance with 4x CPU throttling, no Layout/Paint bands per frame. Attach the strips to the PR. The motion's E2E assertions pause at the first or last frame (`stack-motion.spec.ts`: `__pauseMotion`), never race the 220 ms beat
- performance changes (#275): `npm run perf:audit -- --base http://localhost:<port> [--seed-file <scratchpad file>]` against a served production build, before and after, both tables in the PR (`scripts/perf-audit.mjs`: load, resting board, task sheet, drag, timer tick; usage and how to seed a real production build in its header). Never in `test:e2e` or the gate. Compare its counts (requests, kB, frames, restyled elements): timings move by up to a third on a busy machine
- spacing or size changes: `grep -rn 'toBe(\|toBeCloseTo(' tests/e2e` for hard-coded pixel boxes (#220)
- Rust changes: `.claude/rules/persistence.md` (`cargo test --lib`)
